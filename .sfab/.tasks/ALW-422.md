# ALW-422 Starter QA sweep — dogfood verification of implemented surfaces (Group)

## Context

The starter has a real ERP surface — auth/orgs, catalog, documents + payments, settings/RBAC, org-agent chat, global shell — and the first dogfood pass (2026-07-08) produced [[ALW-419]] and [[ALW-421]], both merged. This Group organises the systematic follow-up: one QA session per area, covering **UX quality** (look and feel, responsive, accessibility) and **functional correctness** (does what we implemented actually work).

**The framing has changed.** This was written as pre-launch dogfooding — verify our own surfaces before strangers see them. **The starter is now public**, so the remaining sessions are post-launch quality on live software that real visitors use. Same work, higher stakes, and no launch gate above it: [[ALW-479]] closed when the launch happened.

Method per child: run the app locally, drive it with browser QA at desktop and mobile viewports, capture screenshot and video evidence, log findings in the session tracker, and file confirmed defects as draft fix tasks. **QA sessions verify and report; they do not fix.**
