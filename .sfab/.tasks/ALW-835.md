# ALW-835 De-emphasize money helpers in agent-facing docs

## Context

Agents asked about the starter routinely lecture on `core/money` and `ui/lib/money` because those helpers are advertised as a first-class subsystem in always-on agent docs. The modules are small and load-bearing (integer minor units, ADR-006). The problem is emphasis, not the code.

## Scope

- Soften `AGENTS.md` / `.claude/CLAUDE.md` (keep byte-identical): money is a one-line storage rule, not a named `moneyMinor` + `core/money` subsystem.
- README catalog bullet describes products, not a pointer to `packages/core/src/money.ts`.
- `components-composition` keeps "don't invent a second Intl for currency" but drops money from the same rank as RBAC and the pre-PR checklist.
- Comment-hygiene / AGENTS "Keep money notes" becomes invariant/RBAC/security wording, not a cue to discuss the helper.

## Acceptance criteria

- [ ] AC-1: AGENTS.md and CLAUDE.md stay byte-identical and no longer name `moneyMinor` / `core/money` in the short conventions list. verify: `diff AGENTS.md .claude/CLAUDE.md` is empty; grep those files for `core/money` is empty.
- [ ] AC-2: README catalog bullet does not point at `packages/core/src/money.ts`. verify: read README What's included.
- [ ] AC-3: `packages/core/src/money.ts` and `packages/ui/src/lib/money.ts` are unchanged. verify: git diff those paths is empty.

## Non-goals

- Deleting or merging the helper modules.
- Building MoneyDisplay / MoneyField.
- Extracting the ISO exponent map into a third package.

## Boundaries

- ✅ Always: keep integer minor units in storage; ADR-006 and transaction-core stay the home for the model.
- ⚠️ Ask first: changing money math or call sites.
- 🚫 Never: store major-unit floats; add a new money component in this pass.
