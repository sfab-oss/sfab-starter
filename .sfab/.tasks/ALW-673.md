# ALW-673 Starter: logging convention — V1 ops light, V2 activity later

## Context

Platform landed a structured logging helper + convention ([[ALW-662]]) and Biome `noConsole` ([[ALW-671]]). Starter had neither. This findings task decided the starter approach.

## Decision (2026-07-24)

**Split ops logs from ERP activity. Ship light ops logging first; activity UI later.**

| Layer | V1 now ([[ALW-700]]) | V2 later ([[ALW-699]]) |
| --- | --- | --- |
| Purpose | Workers Logs / debug | User-facing “what happened on this item” |
| API | `@workspace/log` `structuredLog` | Separate `recordActivity` (or similar) |
| Sink | Console JSON only | Persist (D1) + list by entity |
| UI | No | Activity tab/panel on an entity |

Copy platform helper **shape** (typed kinds, zero-dep package, then `noConsole`), not platform’s ~180-kind registry. Keep `hono/logger()` in V1. Do **not** dump ops errors into a future activity feed.
