# ALW-832 Fix missing error, loading, and org-restore states

## Context

[[ALW-482]] / [[ALW-428]] UX walk (2026-08-21, `origin/main` `042e7d7`) found three broken-state issues on live starter surfaces. Unknown product URLs hang on a blank loading bar. After sign-out + sign-in the org switcher shows `??` / No Organization on Home even though catalog data still loads. First-paint loading shells blank the org switcher and hide chat. Every navigation also hydrates with a React mismatch on `<html className="light">`.

## Scope

- Unknown resource IDs (at least catalog product; match entities/documents if they share the same pattern) show a real not-found or error state with a way back to the list. Not a stuck skeleton.
- After login, the org switcher shows the active org as soon as Home is interactive. No `??` / No Organization flash that outlives the page content.
- Loading shells keep shell chrome (org switcher, chat launcher) usable or visibly skeletoned with names. Entity detail loading is not an empty canvas with only "Loading entity…".
- Remove the html class / color-scheme hydration mismatch (theme class must match between SSR and client).

## Acceptance criteria

- [ ] AC-1: `/catalog/<unknown-id>` shows an error or not-found state and a path back to the catalog list. verify: open `/catalog/does-not-exist` signed in as demo; no infinite loading bar
- [ ] AC-2: Sign out, sign in as `demo@sfab.dev`. Home org switcher reads the demo org once Welcome is visible. verify: screenshot of Home immediately after login
- [ ] AC-3: Navigate to entity detail and settings. Org switcher is not an unnamed disabled button; chat launcher stays in the tree. verify: first-paint snapshot
- [ ] AC-4: Browser console has no hydration mismatch on `html` `className` / `color-scheme` for login and a protected page. verify: console on `/login` and `/catalog`

## Non-goals

- Visual redesign of lists/details/dialogs (that is the layout follow-up).
- A11y labels, i18n leftovers, chat dock focus.
- A throwaway empty org; seed org is enough.
- Live agent replies.

## Boundaries

- ✅ Always: reproduce on local `:4011` with seed demo user; keep unknown-id handling consistent across catalog/entities/documents if the loader is shared.
- ⚠️ Ask first: changing auth session restore beyond what is needed to show the active org.
- 🚫 Never: prod data; swallowing the 404 by redirecting without an error state.
